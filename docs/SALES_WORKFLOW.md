# 从候选咨询到真实成交

OpenFind的目标是帮助销售找到适合的人、开展有价值的交流并保留结果依据。评论表达过需求，只是起点。所有阶段和金额都是人工登记，平台发送、客户回复、付款与履约不能由评分或模型推断。两平台普通账号可通过本机官方网页版同步会话，人工确认后单次发送并回查平台消息标识；模型只生成待审草稿。支付系统尚未接入，不将聊天或测试回执当作真实成交。

## 先定义能卖给谁

在客户跟进 → 沟通成交工作台 → 真实业务资料中填写身份、产品/服务、地区、真实价格范围、可提供的具体帮助和可核验资料。产品、规格、地区、交付能力不匹配的咨询不应优先联系。此前的家居数据是测试样本，不能据此假设用户实际销售家居商品。资料未填时不编造卖点或生成首句。

优先级应综合：真实需求与产品匹配、评论与回复的新鲜度、是否还在寻找、可解决的具体问题、对方是否愿意继续交流。点赞多、评论多、模型高分不是成交依据。旧评论先确认需求是否仍存在；已经买到、拒绝联系或敏感个人语境不用于继续营销。

## 每次交流只推进一个明确动作

| 阶段       | 销售要做什么                                                         | 推进依据                                  | 目标                               |
| ---------- | -------------------------------------------------------------------- | ----------------------------------------- | ---------------------------------- |
| 首次接触   | 透明说明身份，回应用户原问题，提供一个具体帮助，问一个容易回答的问题 | 可提供匹配产品或真实资料                  | 对方愿意回复                       |
| 获得回复   | 先复述对方的问题，了解用途、规格、地区和当前解决方式                 | 实际客户回复                              | 确认需要解决的问题                 |
| 确认需求   | 了解行动时间、预算范围和影响选择的关键顾虑，避免一次连问十个问题     | 客户原话支持需求与时间                    | 判断是否适合继续                   |
| 提供方案   | 给1–2个真正匹配的选项，说明价格、包含项、差异、交付及限制            | 人工核验产品/服务信息，实际方案或报价记录 | 客户能够做选择                     |
| 处理顾虑   | 先问清顾虑属于适配、信任、预算还是时机，再提供对应证据               | 客户明确提出的顾虑                        | 解决一个真实障碍                   |
| 确认下一步 | 约定具体动作、责任人和时间，比如核对尺寸、确认方案、平台下单         | 双方实际约定                              | 可执行的小承诺                     |
| 登记成交   | 保留订单/成交记录、凭证说明或编号和金额                              | 人工登记的证据                            | 分开统计真实与演示记录             |
| 复盘       | 找出在哪一步无回复、不匹配或流失，修正来源选择、价值内容和方案       | 实际沟通与结果记录                        | 提高有效回复和成交，而不是堆积线索 |

例如用户问“花瓶链接给一个”，若确实出售相近产品，可以透明说明自己是销售，并提供真实材质与尺寸资料，问“你是只找原款，还是同尺寸的替代款也可以？”不能冒充原博主、假称拥有原款链接，或在不了解对方需求时直接宣称最低价。

如果对方说“太贵”，先了解比较的是总价、配置还是预算约束，展示真实选项与差异；不要编造限时优惠、库存或成交案例。若只是收集灵感，允许对方暂时不买。未回复不连续催促，后续跟进应来自客户同意、双方约定或新的有效互动。明确拒绝后停止主动联系。

## 当前产品中的执行路径

1. 客户线索 → 查看与跟进：查看原评论、原始日期、上下文和判断依据。
2. 填写真实业务资料后，按当前阶段准备本地草稿。首条尚无回复时不会生成连续催促；同一用户在其他作品下已有联系记录时，提示在原记录继续。
3. 打开原作品，在平台核对具体用户并人工沟通。链接是原作品入口，不是私信API，也不表示已发送。复制草稿不推进销售阶段。
4. 在工作台粘贴实际发出内容、客户回复、内部备注、方案/报价或订单说明；每次提交有独立ID，重复请求不重复记账。
5. 根据客户回复填需求、行动时间、预算、顾虑、下一步及跟进时间，保存销售进展。到期跟进在客户页显示，点击可回到对应客户；这是页面待办，不是后台自动通知。
6. 阶段推进有证据约束：未有发出记录不能记为已联系；未有客户回复不能记为需求已确认；方案/报价和订单证据不完整不能登记成交。
7. 登记“对方拒绝联系”会清空后续跟进，并在同来源、同平台、同一用户的其他线索中继承停止标记；不跨平台推断身份。既有成交不会因为后来拒绝联系而被当成退款或删除。

客户页旧的“qualified”标记改称“需求已确认”，不再叫“已转化”。工作台的销售阶段与这些旧线索标记分别保留；成交统计只读取有凭证说明和金额的销售记录，并标注为人工登记，不伪装成已核验付款。

## 平台连接边界

在“私信工作台”中同步本机官方网页版会话，并按同平台公开用户标识绑定真实线索。可逐会话启用60秒检查与新来信模型建议；发送仍逐条人工确认。消息以平台原始标识去重，未知发送结果只读核对、不自动重发。拒绝联系和账号异常会暂停。接入方式及实测范围见 [PRIVATE_MESSAGES.md](PRIVATE_MESSAGES.md)。

[抖音企业机构账号用户服务协议](https://lf26-cdn-tos.draftstatic.com/obj/ies-hotsoon-draft/douyin_agreement/b482fa28-25db-4b0a-8840-2a4a1882cd35.html)要求真实经营身份，并禁止垃圾信息、过度营销和与评论内容无关的信息。小红书同样强调真诚分享、友好互动与用户信任，参见[官方社区规范说明](https://pgy.xiaohongshu.com/help/detail?id=1eda0a065dd894063c2e029a49e8f6a1&userType=4)。本地频率限制不能保证账号不会被平台限制。

## 接口与数据

- `GET/PUT /api/sales/profile`：本机真实业务资料，不自动发送模型。
- `GET /api/sales/export`：下载本机销售记录JSON，包括事件与成交说明，不含模型Key。
- `GET /api/sales/summary`：真实/演示分别统计联系、回复、人工成交、金额和到期跟进。
- `GET/PUT /api/leads/:id/sales`：销售阶段、需求、下一步；revision冲突返回409，避免覆盖他人修改。
- `POST /api/leads/:id/sales/events`：只登记已发生的沟通；UUID去重。不是发消息接口。

销售记录以独立实体保存在本机，重新搜索或复核线索不会覆盖对话历史。已登记事件不提供静默删除；500条上限会显式停止新增，保留已有记录。
