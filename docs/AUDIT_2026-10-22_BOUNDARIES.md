# 恢复限制与事务边界复核

## 修复

- **外层事务回滚导致占用记录丢失**：请求日志原先通过嵌套保存点写入，但释放保存点并不代表外层事务已经提交。现在未提交事务内禁止发送新的网络请求；无 scope 的发送也受此约束。发送前后置检查覆盖 preflight 开启事务的情况。
- **异步事务越过回滚边界**：事务回调要求同步完成，并通过异步上下文保留禁止发送的限制。即使误传异步回调，在同步回滚之后继续执行，也不能发出新的付费请求。
- **并发读后写失败**：外层事务使用 `BEGIN IMMEDIATE`，在读取需要更新的状态之前获取写锁，避免另一个进程提交后，当前 WAL 读快照无法升级写事务，导致已返回的响应无法保存。内层保留保存点及回滚语义。
- **内存版本提前推进**：页检查点和工作流版本现在在最外层提交成功后才更新内存对象。回滚不会留下一个恰好匹配另一进程新版本的旧对象，避免再次写入时覆盖新进度。
- **浏览器来源绕过恢复限制**：无首屏检查点的恢复任务切换到浏览器，以及浏览器指定链接解析，现在都检查恢复限制，不能绕过 API 请求层的保护。
- **工作流裸写入**：复核接口收尾改用带版本比较的保存函数，避免绕过并发检查。
- **子任务限制持久性**：恢复限制继承不能在未提交事务中执行，避免继承标记回滚后仍继续执行子任务。

## 验证

- `npm test`：218 项通过。
- `npm run build`：通过，包含 TypeScript 检查；保留已有 bundle 大小提示。
- `npm run test:e2e`：21 项通过。
- 修改文件 Prettier 检查与 `git diff --check`：通过。
- 新增回归覆盖：真实子进程在读取后遭遇另一写进程；事务回滚后的响应重放且只调用一次 transport；嵌套事务回滚后的内存分页及工作流版本；异步事务续执行禁止发送；恢复流程修改参数、供应商身份并创建新的子任务后仍禁止发送；切换浏览器后在发起任何请求前停止。
- 所有验证使用临时数据库、模拟供应商响应及本地服务，未使用真实付费接口。

## 边界

恢复限制绑定原任务/工作流及其子任务，不随 URL、参数或供应商凭证变化而解除。用户核对供应商记录后显式创建的独立任务仍可以执行，不自动认为其免费。供应商已经执行但响应尚未持久化时发生进程崩溃，仍无法凭本地信息证明未计费：继续保留不确定标记并禁止自动重发，不承诺找回供应商未提供恢复接口的结果。
