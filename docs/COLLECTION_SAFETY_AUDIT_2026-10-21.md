# 采集安全检核（2026-10-21）

本轮以四条约束检核：凭据不得随重定向流向其他地址；账号身份变化后不得复用旧分页；已访问分页不得因恢复而重放；尚未返回首页的供应商任务也必须保留来源身份。

## 修复

- 高级 HTTP 数据源禁止自动重定向，避免 307/308 转发含 Cookie 的 POST 请求体。回归测试通过本地两个 HTTP 服务验证目标服务没有收到请求。
- 抖音 HTTP 数据源指纹纳入实际 Cookie（包括仅保存在内存中的 Cookie），使用结构化编码后哈希。Cookie 轮换会使旧缓存和旧分页失效，指纹不输出原文。
- 循环分页保留当前进度和已访问游标。恢复时先拒绝循环游标，既不丢弃已保存结果，也不重新发送已访问页面。
- 流程恢复保留尚无首页检查点、但已绑定数据源的子任务。执行器在此阶段也校验来源，防止暂停等待期间切换供应商后重新开始采集。

## 验证与边界

- 新增/扩展回归覆盖 Cookie 轮换、循环分页恢复、首页前来源切换、待处理子任务复用、HTTP 重定向凭据保护。
- 全量单元/API 测试 168 项、端到端测试 21 项通过；TypeScript 与生产构建通过。
