# 线索筛选、去重与跟进检核（2026-10-20）

原则：只根据当前评论者的证据判断需求；身份不能由昵称或易碰撞的字符串推断；重复采集应更新证据而非重置人工字段；编辑冲突必须显式提示；拒绝联系在所有入口保持一致。

## 修复项

- **旧需求在本人后续结束后仍推荐。** 同一评论串中，稳定用户标识相同且时间更晚的明确结束表达，会使旧需求退出推荐。其他用户的结束表达和缺少用户 ID 的评论不能代替本人证据。评论串遍历现在包含嵌套回复，并保留循环/深度保护。
- **致谢被误认为需求结束。** 致谢同时包含继续咨询、提问或新需求时不再降级；致谢发生在作者答复之前也不作为答复后的结束证据。
- **新“同求”被旧主评论日期拖累。** 近期同求可以承接旧主评论的明确商品指代，时效取当前回复；敏感主题、作者本人及排除条件仍保留。
- **询问成本掩盖新的委托。** 混合评论中明确提出自己的装修或设计需求时，不再仅因同时询问既有成本而排除。单纯比较旧成本仍不推荐。“我家有一个、还想买一个”也不再仅因“我家有”被当成卖家。
- **去重身份不完整或拼接碰撞。** 新 ID 使用编码后的结构化键，包含来源、平台、作品及用户/匿名评论身份类型；平台缺失时从作品补齐，匿名评论不会与恰好同 ID 的真实用户误合并。
- **重复采集受输入顺序或分数排序影响。** 手动采集与工作流统一入库，按原评论时间选择更新证据，同时间用 ID 稳定排序，不再由先输入或较高分决定。复用历史记录 ID，保留销售记录和流程引用；人工状态、备注、话术、创建时间和人工版本号保持不变。
- **人工备注和话术静默覆盖。** 线索 PATCH 必须携带 revision；旧版本返回 409，缺少版本返回 400。前端保存成功后更新版本，冲突时保留输入并提示重新打开核对。该版本仅针对人工编辑，自动证据更新不会无意义地阻断人工保存。
- **实际回复中的拒绝未生效。** 手工登记的 incoming 回复采用与私信同步相同的明确拒绝规则；无需额外选择 optout。已停止联系的记录不能通过保存重新写入跟进日期；导出使用有效停止状态，同用户关联线索继承保护。

规则版本升级为 `intent-rules-3.2.0`。

## 验证覆盖

新增测试覆盖旧主评论的新同求、本人/他人/匿名身份、嵌套回复、致谢伴随新需求、成本询问伴随新委托、身份分隔符碰撞、旧 ID 与销售历史保留、重复采集保留人工字段、低分但较新证据优先、并发人工编辑冲突、实际拒绝和停止后的跟进导出。

153 项全量测试、18 项工作流专项测试（含全量运行后追加的较新证据回归）、20 项浏览器测试通过。生产构建、修改文件格式检查及 diff 检查通过。浏览器验收覆盖完整线索采集、客户编辑、销售沟通与刷新持久化。测试使用独立临时数据，不向客户发送消息。

## 业务边界

去重单位是“来源 + 平台 + 作品 + 稳定用户标识”，而不是昵称。同一人在不同作品下可能表达不同需求，因此保留独立需求记录；客户跟进仍按同平台、同来源、同用户关联，避免重复接触并传播拒绝联系状态。历史已有记录不做破坏性合并或删除，以免丢失不同记录中的人工证据。

手工采集允许用户明确保存非自动推荐的评论；自动工作流仍要求近期明确需求。归档或已有成交记录不会因规则复核被自动重置。规则判断仍需人工确认，不声称可以理解所有否定、转述和复杂语义。
