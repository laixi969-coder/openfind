# 知识库

把运营经验沉淀成「方法卡」，让 AI 改写用你的结构、钩子与禁区，而不是每次从零开始。小红书与抖音各一套，互不覆盖。

## 卡片结构

| 字段     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 平台     | `小红书` / `抖音` / `两个平台通用`；检索时只取同平台与通用卡 |
| 类型     | 选题、结构、钩子、表达、痛点、反对、成交、禁区               |
| 结论     | 一句话，进 prompt 的就是这一行                               |
| 怎么用   | 具体做法；比抽象形容词有用                                   |
| 标签     | 检索依据，决定改写时能不能被取到                             |
| 原话依据 | 逐字引用的评论或正文；拆解/归集产出的卡必须至少有一条        |
| 启用     | 停用后不参与检索，用于淘汰过期经验                           |

数据存 `data/openfind.sqlite` 的 `insights` 实体，随现有备份一起迁移。

## 四种来源

1. **手写**：直接新建，适合表达习惯、禁区、成交话术。
2. **拆解作品**：选一篇已采集作品，提取选题角度、段落功能、钩子类型、语气与评论区卡点；同页还有「分析账号」，按已入库的同一作者作品归纳选题规律。
3. **评论归集**：按平台（可限定单篇作品）取最近 N 条评论，归纳痛点与反对意见。
4. **成交**：目前从销售工作台人工整理，未自动生成。

拆解与归集的产出**先作为候选返回**，勾选采纳后才落库，不会自动污染知识库。

## 拆解一篇作品拿到什么

一次拆解同时给三样东西：

1. **方法卡候选**：选题（写给谁、切什么场景、承诺什么收益）、结构（段落功能与顺序）、钩子（开头句式）、表达（语气与人称）、痛点与反对（来自评论区）。每条卡必须带逐字原话，找不到依据的会被丢弃并计数。
2. **数据雷达**：六个维度——点赞、评论、收藏、讨论度（评论/(评论+点赞)）、收藏率、新鲜度。画的是**相对同批作品的分位**：对比样本优先取命中该作品的同关键词搜索任务，没有就退回同平台已采作品。分位 80 表示高于 80% 的同类作品，**不是平台全量排名**；样本少于 5 篇会在面板上提示。
3. **评论区高频诉求**：本机按意图句（价格/避坑/教程/选品/场景）提取并计数，不是模型总结，可逐条复核。

## 分析一个账号

只用**已入库**的该作者作品（≥3 篇），不新抓主页。输出账号级的选题卡与结构卡，并列出参与分析的作品与互动数。

和“把主页整个抓下来分析”的差别要说清：样本是你导入的多少，不是主页全量；因此结论只覆盖已入库那几篇，不宣称代表整个账号。要更完整的画像，先在发现作品按作者名搜索，或用粘贴链接导入同一作者的 3–5 篇。

## 检索规则

按平台过滤后打分：类型权重（禁区 6 / 选题·结构 5 / 钩子 4 / 表达 3 / 痛点·反对 2 / 成交 1）+ 同平台 2 分 + 标签重合 ×3。

禁区类卡片按平台**永远带上**，最多 3 条，不与其他卡抢名额。

不引入向量库：几百张卡的规模用标签匹配足够，且结果可解释——你能看懂为什么用了这张卡。

## 搜索词挖掘

平台没有下拉词接口，硬爬下拉框会触碰账号保护，所以改成**从已采集评论反推**：

- 逐句匹配意图词（价格/避坑/教程/选品/场景），命中后清理语气词与链接，得到用户真的会搜的短语。
- 纯本机统计，不发任何新请求；按命中次数与是否包含种子词排序。
- 配了大模型会额外补 10 个长尾词；模型调用失败只返回本机结果，不阻断。
- 「去搜索」把词与平台交给发现页，仍由你手动点搜索。

## 选题池

把「评论区在问什么」直接变成可写的题，不调模型、不编主题：

- 来源只有一处：该平台已采集评论里的**真实提问**。出现次数就是问过的人数。
- 标题由规则拼：短语 + 意图后缀（价格→预算怎么拆、避坑→容易踩的坑…），控制在 20 字内；短语短于 6 字直接丢弃，因为没有主语，当标题会像半句话。
- 每个选题附一句写法建议（按意图给），以及触发它的评论原话，可逐条核对。
- 「去创作」把标题带进新建草稿，正文仍需自己写或去克隆参考作品。

它的价值不在“AI 帮我想题目”，而在于**题目是用户自己问出来的**。评论样本少时池子就浅，这是刻意的：宁可少给，也不拿模型编的话题充数。

## 效果归因

按搜索任务把「搜索词 → 作品 → 线索 → 成交」串起来，同一作品只计入首次命中的关键词。

这是本产品相对通用内容工作台多出来的一环：不只看曝光，而看哪个词真的带回了线索与成交。金额只取已登记的成交记录，第三方评论本身不等于成交。

## 累积与进化

知识库要能进化，必须有「变异 → 选择 → 遗传」三段：生成候选是变异，判断哪张卡有用是选择，保留并强化是遗传。目前只做到前一段和选择所需的数据记录。

已实现（P0 + P1）：

1. **草稿记录引用了哪些卡**：克隆创作里点「AI 改写」并套用结果时，`Draft.knowledgeIds` 写进草稿；只点改写不套用、或手动改，则不算引用。
2. **发布后回填作品数据**：系统不代发，草稿卡片提供「发布后回填作品链接」，用已配置的数据源拉一次真实互动数（赞、评论、收藏）存进 `Draft.result`。每次回填或刷新消耗一次数据源请求。
3. **聚合展示**：知识库「效果归因」里按卡片统计「带出草稿数 / 已回填作品数 / 互动数」。

口径必须清楚：**互动数是作品级数字**。一篇作品用了 5 张卡，这 5 张卡上都会各记一次同一组数字，所以卡片之间不能相加；总计按草稿去重。

暂不实现（P2 / P3），门槛如下：

- **自动降权 / 淘汰**：需要至少 50 张被用过的卡、30 篇已回填作品。低于这个量，所谓「效果排序」是在用运气调参。
- **卡片效果加权排序**：需要先有对照组。可用的做法是「留一法」——每次改写随机留一张卡不用，比较两组结果；不是把点赞高就直接加权（点赞受发布时间与平台分发影响，不等于内容质量）。
- **自动采纳卡片**：不建议做。模型生成的卡有系统性偏好，长期全自动会让知识库同质化，把你自己的语气磨掉。当前设计固定为「机器挖候选、人做判断」。

补齐 P2 需要的数据能力：发布后按作品追踪回采（现在采集是按关键词搜索，不按作品追）。这是下一步的主要工程量。

## 边界

- 方法卡正文会随改写请求发送到你在连接设置里配置的模型服务；介意的话用本机模型或不要放敏感信息。
- 卡片内容是资料不是指令：注入时会明确告知模型不要执行卡片里的要求。
- 拆解与归集需要配置大模型；未配置时搜索词挖掘仍可用（纯本机）。
- 不做全自动采纳、不自动改写、不自动发布。
