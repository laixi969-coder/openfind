# 核心采集流程检核（2026-10-20）

本轮检查四条业务不变量：采集数据与进度必须一致；暂停不能接受迟到响应；恢复优先利用已持久化的成果；缓存必须对应同一任务、平台、来源及真实结果数量。

## 修复

1. **完成子任务后重启会重复执行。** 原流程先清空 currentJobId，再推进父步骤，中间存在不可恢复窗口。现在保留子任务引用直至父步骤推进；恢复时直接吸收已完成子任务，不受五分钟缓存时效限制。
2. **中断分页从第一页重跑。** 每页保存下一游标、已访问游标及数据源指纹。恢复同一子任务并保留已有结果计数；更换数据源或账号后阻止把旧游标发送给新服务。末页落盘但完成状态尚未落盘的任务，可直接完成。
3. **实体与进度分开写入。** 新增 SQLite 保存点事务，将整页实体、结果 ID、计数、页数和检查点一次提交；任意写入失败整页回滚，内存进度也不前移。链接解析的作品与流程检查点同样原子保存。
4. **异常子任务的部分结果未回收到父流程。** 即使执行器抛出异常，也将已保存的部分结果合并到父流程，并标记子任务失败或停止，避免持续显示运行中。
5. **游标循环识别不完整。** 执行器记录历史游标，识别 A → B → A；先保存有效本页，再停止重复请求。
6. **跨作品、跨平台或来源冲突的数据可覆盖持久化记录。** 保存前检查整页身份；错误评论归属和既有 ID 的身份冲突整页拒绝。缓存也核验真实实体来源、平台、评论归属及计数。
7. **不足请求数量的末页重复请求。** 明确区分“真正耗尽”和“因数量上限截断”。耗尽后的空结果、少量结果可在原有五分钟窗口复用；截断末页不能作为更大数量请求的完整缓存。
8. **RedFox 本地拒绝误记为付费提交不确定。** 在写入提交占位记录之前检查取消状态、Key 和请求额度。尚未发出的请求不再阻断后续重试；真正发出后丢失响应的情况仍保留不确定记录，禁止自动重复提交。

浏览器读取资源清理最多等待三秒，避免已取消的采集因为清理请求而持续占用执行槽位。

## 回归方式

- 注入 SQLite 写入失败，验证实体和进度一起回滚，并验证嵌套事务。
- 模拟子任务已完成、父流程尚未推进的重启窗口，验证不重发搜索。
- 使用本地 HTTP 模拟数据服务运行真实执行器，验证暂停恢复只请求下一页；取消后的迟到响应不入库；循环游标停止；指纹变化时零网络请求。
- 验证短页、空页、截断末页、计数损坏及跨来源覆盖的缓存行为。
- 模拟 RedFox 取消和额度不足，验证没有生成虚假的不确定任务。
- 最终 `npm test`：144 项全部通过；`npm run build` 通过，保留已有主包体积警告。修改文件格式检查和 `git diff --check` 通过。
- 20 项浏览器流程测试通过。全部测试使用独立临时数据库，不接触真实平台账号或产生供应商费用。

## 边界

持久游标恢复用于供应商 API、高级 HTTP 适配器和演示任务。内置浏览器游标依赖临时页面会话，不能跨暂停或重启可靠复用；未完成的浏览器步骤仍需重新读取，已完成步骤和已有结果会保留并去重。

本地取消不能撤销已经发出的远程请求，也不能保证供应商不计费。若远端已经计费但响应在落盘前丢失，仅凭本地检查点无法实现端到端“恰好一次”；RedFox 提交已有单独的不确定状态保护，其他 API 的重试仍由用户明确恢复触发。

已有未带检查点的历史任务保持兼容，但无法补造过去没有保存的分页游标。供应商游标过期会明确暂停并保留已有结果，不自动从头重试。
