# 草稿素材持久化检查（2026-10-21）

## 保存约束与实现

草稿保存成功前，远程 HTTP(S) 图片和上传的 data URI 图片必须备份到本地，草稿中只写入对应的 `/api/media/…` 地址。现有本地素材和随应用提供的演示素材继续使用原引用。旧草稿再次保存时也执行此流程。

- 使用既有安全下载器，限制公网地址、重定向、响应大小与超时；下载后校验 PNG/JPEG/WebP 文件签名。
- 按内容 SHA-256 命名文件，同内容不同来源只保留一份；按来源摘要持久化备份索引，相同来源的并发请求共享下载。
- 先写权限为 0600 的临时文件，刷新文件、原子重命名并刷新目录，再记录索引和提交草稿；临时文件不通过素材接口暴露。
- 重复保存先校验缓存文件摘要。文件缺失或损坏时重新下载修复；远程链接已失效且没有有效本地副本时明确失败，不提交缺失素材的草稿。
- 任意一张图片失败，原草稿保持不变，错误指出失败图片序号。已完成备份保留供下次重试，失败请求不永久占用并发缓存。
- 下载完成后重新检查草稿版本。下载期间草稿被修改或删除，旧请求不会覆盖新内容或复活删除记录。
- 编辑器在没有后续编辑时接收服务器返回的本地图片地址；如果用户仍在编辑，保留当前内容和未保存状态。

## 验证

新增 `tests/draft-media.test.ts` 覆盖：并发和重复保存、不同来源内容去重、独立进程恢复且不重新下载、批次部分失败后重试、缓存文件缺失/损坏修复、非图片响应拒绝、草稿 API 本地化、素材访问与导出、备份失败保留原草稿、下载期间新版本保护。既有浏览器回归继续验证保存响应迟到时的编辑保护。

## 范围边界

这次修复替代创作流程检查中“保存仍依赖远程原链接”的限制。尚未再次保存的旧草稿不会自动扫描下载；已经失效且从未备份过的素材无法凭空恢复。备份文件与 SQLite 索引都位于应用数据目录，迁移或备份应用时需一起保留整个目录。未引用的成功备份暂不自动清理，避免误删重试或其他草稿共享的素材。进程崩溃遗留的临时文件不会成为有效素材引用。
