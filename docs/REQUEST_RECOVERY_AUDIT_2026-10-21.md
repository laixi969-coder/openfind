# 并发、超时与崩溃恢复检核（2026-10-21）

## 已修复的边界

1. 同一任务的重复执行可能覆盖取消控制器并重复请求。执行器现在拒绝同进程内的重复启动。
2. 原先只有分页检查点，请求成功但分页落盘前中断会重新请求。新增 SQLite 请求记录，在发送前原子占用请求身份，完整响应读完后先持久化，再交给解析与分页保存。恢复时重放已保存响应。
3. 网络超时、响应体读取中断、发送后进程退出不能证明供应商未计费。此类记录保持未确定状态，同一任务恢复时禁止自动重发。没有靠超时租约自动释放提交权。
4. RedFox 提交任务原先使用分离的读取与覆盖写入，两个进程可同时提交。现在通过唯一键插入领取提交权，并保留独立于采集任务的提交响应；任务编号写入失败后可从响应恢复，无须再次提交。
5. 已确认 processing/pending 的轮询允许下次继续查询；删除旧轮询记录时比较完整记录，防止迟到的消费者删掉新一轮结果。
6. 本地重放不增加供应商请求计数，不再次预占 HTTP 采集动作；本地预算拒绝不会遗留“可能已计费”的提交记录。

## 范围与恢复行为

- 请求记录覆盖采集任务的 TikHub、RedFox、高级 HTTP 分页，以及链接流程中的 API 详情读取。RedFox 评论提交始终使用独立的持久身份。
- 请求身份由任务范围、URL、方法、请求头及请求体计算摘要；不把请求凭据原文写进身份记录。保存的响应正文与业务数据库一同留在本地。
- 已收到并持久化的响应可跨进程重放；未持久化的响应无法在供应商不支持幂等键/结果查询时凭空恢复。对于结果不确定的请求，先在供应商后台核对，再决定是否新建任务。RedFox 可通过已有任务编号补填入口恢复。
- 不对用户明确新建的独立任务做无限期跨任务去重。请求记录目前保留在数据库内，不使用过期删除重新开放不确定请求；后续清理必须保留这一约束。
- 本轮未触及原目录中的备份恢复改动。

## 验证

- 全量单元/API 测试：179 项通过；端到端测试：21 项通过。
- 新增测试覆盖同进程并发、跨进程竞争、发送后 SIGKILL、响应持久化后 SIGKILL、响应体超时、分页写入失败、RedFox 任务编号写入失败、轮询旧响应竞争和请求预算。
- TypeScript 与生产构建通过；本次修改的格式检查通过。
- 供应商请求均使用模拟服务或响应，没有发起真实付费采集。
