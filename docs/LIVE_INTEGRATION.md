## 修复依据

1. 首屏使用 `/aweme/v1/web/general/search/stream/`，旧实现只读取 `single`，漏掉首屏而从后面的作品开始保存。
2. 流式响应是十六进制UTF-8字节长度与JSON帧组成；`ack=-1` 表示废弃此前的临时首屏缓存。必须丢弃缓存再合并后续数据，保留长整数ID精度；截断或无结束标志时报错。
3. 排序切换以请求发起时间和实际排序参数同时隔离。综合排序迟到响应不能进入最新任务。
4. 等待页面加载与筛选控件就绪，必要时通过页面搜索框提交一次。完成采集后解绑监听，保留最后结果页供核对，替换旧的已完成结果页。
5. 页面卡片显示原始发布日期，任务保存平台排序证据；新任务链接包含平台和任务ID，刷新不会回到旧任务。

本轮官方搜索页仍显示“抖音精选”品牌标识，但使用普通 `/search/` 路径且实际返回作品。不能仅凭标识判断登录了错误账号或搜索被禁止。

## 实现与外部边界

API服务与浏览器服务独立运行，各平台使用自己的Chrome profile。读取官方网页正常产生的响应，执行可见筛选、翻页、展开回复与创作者编辑器操作。登录失效、本人验证、权限限制和响应异常会明确停止，不混入演示数据。

发布采用 `prepared → submitting → published / uncertain` 状态机；只有可核对的作品ID与URL才更新成功，不确定时阻止重复提交并提供作品管理核对。发布、搜索与评论不保证永久不受平台页面更新或限制影响。
