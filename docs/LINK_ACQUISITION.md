# 指定作品链接获客

在“一键获客”选择“粘贴作品链接”，粘贴完整作品链接或 App 分享文案。自动识别小红书/抖音、去除重复作品，点击“从链接一键获客”后依次读取作品、采集评论、判断需求并保存候选。界面保留原作品入口、原始评论、入选/排除依据与执行日志。

## 数量与范围

- 推荐一次3条，单次最多5条同平台作品；两平台分批执行。这是 OpenFind 的任务上限，不是平台官方额度。
- 每篇默认20条评论，可设置1–50条，包含已读取的回复。候选只从本次指定作品产生，不进行关键词搜索、热门补充或历史作品扩展。
- 支持小红书笔记和抖音视频/图文。分享短链接必须返回能验证的官方作品跳转；失效、仅支持 App 或无法解析时，需要换成完整作品链接。
- 只接受官方作品地址，不接受个人主页、搜索结果页、直播间、其他网站、带账号密码或自定义端口的 URL。短链接逐跳校验域名与协议，防止跳转到本机或非平台站点。
- 小红书 `xsec_token`、`xsec_source` 会保留，其他分享追踪参数移除。签名过期、私密或删除的作品会明确暂停，不用演示作品替代。

## 真实读取与保护

链接流程始终使用真实模式及本机已登录的内置平台浏览器，不因工作空间处于演示模式而生成模拟结果。高级 HTTP 适配器需先切换到内置浏览器。

每次作品读取占用一个“搜索/作品读取”本地批次，遵守该平台搜索额度和间隔；评论继续按实际采集批次计数。所有额度、间隔、验证码暂停、限流和连续异常保护沿用连接设置。上限不意味着平台许可，也不提供账号不受限制的保证。

作品必须由官方详情响应或页面公开详情数据核实平台和原始作品 ID；不会拿推荐列表第一条充当目标。多条链接按顺序处理，记录每个已完成作品的检查点。暂停后可继续，已经读取或完成评论采集的作品不会重复执行。评论的5分钟有效缓存保持原始读取时间，不延长评论的新鲜度。

仅将近7天有明确需求依据的评论保存为候选；旧评论、日期不明、推广、已购/已解决或敏感主题仍按既有规则排除。敏感主题作品不执行个人营销线索流程。零候选仍显示真实评论和原因，不代表采集失败。模型复核使用已有模型设置，消息发送继续逐条人工确认。

## API 与实现

`POST /api/workflows/links`：`{ "content": "分享文案或多条链接", "commentLimit": 20 }`。返回持久化流程，状态沿用 `/api/state`；暂停/继续沿用 `/api/workflows/:id/pause` 和 `/resume`。

- `shared/work-links.ts`：平台识别、作品 URL 解析、签名保留、数量限制及去重。
- `server/platforms/work-redirects.ts`：受限的短链跳转解析，逐跳检查后才发起下一次请求。
- `server/platforms/linked-work-page.ts`：读取匹配目标 ID 的真实作品详情；验证、删除、身份不符或数据缺失则停止。
- `server/workflows.ts`：新增链接读取阶段，复用评论任务、检查点、线索判断及规则/模型复核。

自动测试使用合成作品和隔离数据库，覆盖两平台管道、错误链接、批量边界、短链跳转、身份不符、验证暂停、恢复和结果页面；真实账号测试另行执行，截图和账号数据仅保留在本机。
