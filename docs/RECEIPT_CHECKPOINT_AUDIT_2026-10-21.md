# 请求记录与分页一致性检核（2026-10-21）

## 修复

- 请求响应增加摘要校验。响应正文与防重发记录不匹配时，禁止重放或重新发送。
- 每页捕获实际使用的响应引用，将业务结果、分页检查点、分页摘要和响应确认放在同一 SQLite 事务中。写入失败时全部回滚，原始响应仍可重放。
- 恢复前校验分页摘要、响应确认归属以及结果是否仍存在；终止页也必须先校验，不能仅凭空游标宣布完成。
- 恢复读取数据库中的最新任务，避免旧内存对象覆盖已提交进度。已开始任务不能改变请求参数，也不能借用另一个任务的缓存掩盖原请求的不确定状态。
- 流程所引用的子任务缺失或已付费子任务参数不匹配时暂停，禁止隐式创建新的计费任务。
- 请求正文与永久防重发标记分开保存。已有请求记录在启动时迁移防重发标记；单独移除响应记录不会重新获得发送权限。
- RedFox 轮询由“删除记录”改为条件状态转换。只有明确标记为轮询且供应商返回 pending/processing 的成功响应才允许下一轮；迟到响应无法修改新一轮状态。
- 增加内部受限清理函数：只有已随分页提交、提交记录与当前结果一致的响应正文可清理。未确定、未提交及提交状态损坏的记录拒绝清理；防重发标记和分页提交凭证不删除。本轮没有对用户数据库执行批量清理。

## 验证

- 全量单元/API 测试：190 项通过；端到端测试：21 项通过。
- 覆盖事务回滚、错误任务归属、响应摘要错配、损坏检查点、陈旧内存对象、正文删除、受限清理、旧记录迁移、待定轮询竞争和缺失子任务。
- RedFox 不确定提交补填已核对的供应商任务编号后能够继续查询；测试确认没有第二次提交。
- TypeScript、生产构建和本次修改文件的格式检查通过。
- 未使用真实密钥进行付费采集；原目录未提交的备份恢复改动不属于本轮提交。

## 边界

这些校验不能恢复供应商已经处理但从未被本地持久化的响应。此类请求继续暂停，需核对供应商记录；不会通过清理记录自动重试。新分页具有完整响应关联，历史分页保留兼容读取，无法追补过去未记录的关联。删除整个数据库或同时手动删除防重发标记不在受限清理保证范围内。
