# 小红书 API 数据源

设置 → 小红书 API 数据源：默认 TikHub，也可切换 RedFox。两家 API Key 独立加密保存，仅向固定供应商域名发送，不上传小红书 Cookie。保存后，新任务使用所选服务。未配置、失败或限流时不会回退模拟浏览。

自动浏览小红书进行采集可能导致限流、账号限制甚至封号。应用已关闭小红书浏览器入口、托管、自动发送与发布。抖音采集方式保持不变。生成、保存、分类、分析、复制和导出保留；最终发送与发布由用户操作。

## 配置与计费

1. 在 [TikHub 控制台](https://user.tikhub.io) 或 [RedFox 密钥管理](https://redfox.hk/dashboard/keys) 获取 API Key，在本地设置页填写，不要写入源码或任务描述。
2. 设置每个搜索/评论步骤的 API 请求上限（默认20次）。完整获客流程有多个步骤，该限制不是整个流程的费用上限。
3. 保存即可。可选“保存并测试一次搜索（可能收费）”读取一页，验证鉴权与数据结构；测试不入库。
4. 搜索、指定链接、作品详情、评论采集均走所选 API。缓存按供应商及密钥身份隔离，已保存内容仍可本地访问。

价格参考核对于2026-10-20；最终以供应商账户对应接口报价、余额及账单为准：

## RedFox 等待与恢复

首次采集评论会提交有界条数任务，然后暂停流程，显示taskId和预计可查询时间。之后继续原流程或重新采集同一作品、相同条数时，查询并复用原任务；重启也不会丢失。完成的任务结果保存在本地以避免重复扣费。

如果提交途中断网，服务会保留“提交结果不确定”，禁止自动重复提交。在供应商后台核对已有任务，将taskId补填到设置页“RedFox 待完成任务”，再继续。切换供应商或更换为另一把密钥不会复用不属于该身份的外部任务。

## 验证范围

自动化测试使用隔离数据库与模拟HTTP响应，覆盖鉴权、密钥隔离、分页、预算、异步恢复及小红书与抖音路由隔离。真实供应商验收需要用户在设置页填写有效密钥并运行付费测试；没有密钥时不声称真实采集已经验证。
