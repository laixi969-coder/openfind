# 响应落盘失败与崩溃恢复检核

## 修复

1. **收到响应后保存失败会丢弃可恢复响应**：完整响应在数据库提交成功前暂存在当前进程中。锁超时、响应写入失败后，继续原任务先重试保存，成功后才向采集器交付响应。不会再次调用供应商，也不会提前确认分页。暂存最多 32 个响应，按字符串内存估算总计不超过 64 MiB；不驱逐已有暂存以容纳新响应。容量不足且持久化也失败时明确提示，并继续保留永久防重发标记。
2. **写盘失败使任务清理中断**：任务状态或收尾日志写入失败时，运行控制器与取消监听仍会释放。后台启动入口捕获失败，输出不含请求或密钥的固定提示，避免未处理的 Promise 拒绝终止服务。
3. **SQLite 自动回滚掩盖原始故障**：清理阶段不会用“事务不存在”错误覆盖原始写盘错误。嵌套事务若自动回滚了整个外层事务，会标记事务已失效；即使调用者捕获内层错误，也不能通过存储写入函数意外进入自动提交，产生部分数据。
4. **错误类型保留**：小红书及抖音 API 客户端保留响应持久化错误，避免误报网络超时，引导用户继续原任务保存暂存结果。

## 验证

- `npm test`：223 项通过。
- `npm run build`：通过（包含 TypeScript 检查，保留已有 bundle 大小提示）。
- `npm run test:e2e`：21 项通过。
- 修改文件 Prettier 检查及 `git diff --check`：通过。
- 用真实子进程持有数据库写锁，缩短测试连接的锁等待时间；确认响应保存超时后，并发继续原请求只保存原响应，transport 总调用次数为 1。
- 用 SQLite 触发器模拟响应落盘失败，在子进程读完响应后 `SIGKILL`，再由另一进程恢复；确认防重发记录仍阻止第二次请求。
- 同时注入响应与任务失败状态写入错误；确认页数和结果数保持 0，解除故障后原任务可继续并保存第 1 页，供应商只调用一次。
- 注入 `RAISE(ROLLBACK)`，验证原错误、嵌套事务失效传播及恢复后的新事务。
- 使用临时数据库、模拟供应商响应和本地 HTTP 服务；未调用真实付费接口。磁盘错误由 SQLite 触发器模拟，未填满或破坏用户磁盘。

## 不可消除的窗口

暂存响应只存在内存中。请求已经到达供应商，但完整响应未持久化时进程崩溃，仍无法从本地证明供应商是否执行或找回该响应。此时保持 pending 防重发标记和原分页，不自动重试网络、不跳到下一页。需要供应商查询/对账或恢复原结果，不能声称实现无条件的“恰好执行一次”。
