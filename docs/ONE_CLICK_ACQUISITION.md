# 一键获客流程

入口：侧栏「一键获客」，或发现作品页顶部。选择小红书/抖音、具体产品或场景词后，点击「一键执行获客」。无需分别点击搜索、每篇评论采集、保存线索。

## 自动执行的步骤

1. 按最新发布搜索，默认最多20篇。
2. 合并同平台、同模式、同关键词历史搜索发现的作品。历史作品可能仍有近期咨询，不把发布时间旧等同于需求失效。
3. 结合已保存评论，按近期明确需求、近期讨论、待核实评论信号排序。优先小样本采集，默认最多3篇，每篇20条，包含回复。组合选样会尽量保留至少1篇本次最新搜索的作品，单篇采样则仍优先已发现的近期明确需求。搜索未给出评论数量时标明「待核实」，不当作确认没有评论。
4. 有评论信号的作品不足时，按顺序补充相关搜索、少量高互动搜索；可在设置里关闭。补充搜索仍受每日额度限制，额度不足时保留已搜到的作品继续采样。
5. 用评论原始时间和需求规则判定，仅近7天、明确需求且未被排除的候选自动保存到客户线索。作者自答、推广、已解决需求、缺失日期和敏感主题不进入候选。
6. 同一页展示本次作品、评论、候选、判断理由、日志及平台排序凭据，可导出本次候选CSV。

本流程不会自动发布、评论、私信或添加联系人。候选是待人工核对的信息，不是已获得营销同意的客户，也不代表已经成交。

## 暂停与继续

- 运行时可暂停；已采集数据保留。
- 验证码、登录失效、平台限制、主线额度不足或连接失败时暂停。本人处理官方页面后，在连接设置恢复平台，再回到原流程点击「继续流程」。
- 完成的搜索与作品步骤不会重跑；中断的单个步骤会重试并按ID去重。评论分页游标可能失效，因此不承诺从同一网络游标继续。
- 服务重启后，未完成流程转为暂停，等待用户继续，不在后台自动重试。
- 流程之间、手动采集和发布之间有互斥；采集遵循配置间隔（默认15秒），共用原有平台保护额度。暂停、重试和重启均不会清空额度。符合5分钟缓存条件的本地结果可在网络额度用尽时复用，不延长原始读取时间。
- 原始结果不足上限、或没有满足条件的线索，会按实际数量完成并解释原因，不补充演示数据。

## 实现边界

流程记录存储在SQLite `workflows` 实体，子搜索/评论任务仍存储在 `jobs`。每个流程保存输入、阶段、已完成作品、结果ID、子任务和日志；刷新页面通过 `/api/state` 恢复显示。控制接口为 `POST /api/workflows`、`POST /api/workflows/:id/pause` 和 `POST /api/workflows/:id/resume`。

策略采用本地可解释规则，不依赖未经配置的大模型；规则详见 [获客策略](ACQUISITION_STRATEGY.md) 和 [线索判断](LEAD_QUALIFICATION.md)。匹配地区、具体产品、预算与服务能力仍需人工复核。
